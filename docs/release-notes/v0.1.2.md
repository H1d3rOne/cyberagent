# CyberAgent v0.1.2

## Highlights

- Local Daemon / Web API Foundation for future Desktop/Web Console integration.
- Authenticated local HTTP API with a stable `/api/v1` JSON envelope.
- Async safe Web scan jobs launched through the daemon, with job status and cancel MVP.
- Read/write API coverage for runs, reports, artifacts, events, approvals, and resume-approved flows.

## Features

- Local daemon:
  - `cyberagent daemon`
  - Default listen address: `127.0.0.1:8787`
  - Bearer token file auto-create/load with `0600` permissions on supported platforms.
  - Configurable `--listen`, `--runs-dir`, `--token-file`, and `--max-concurrent-jobs`.
- HTTP API:
  - `GET /api/v1/healthz`
  - `GET /api/v1/version`
  - `GET /api/v1/doctor`
  - `GET /api/v1/plugins`
  - `GET /api/v1/plugins/doctor`
  - `GET /api/v1/runs`
  - `GET /api/v1/runs/{run_id}`
  - `GET /api/v1/runs/{run_id}/report?format=json|md`
  - `GET /api/v1/runs/{run_id}/artifacts`
  - `GET /api/v1/runs/{run_id}/events?cursor=&limit=`
  - `GET /api/v1/runs/{run_id}/approvals`
  - `POST /api/v1/runs/{run_id}/approvals/{approval_id}/approve`
  - `POST /api/v1/runs/{run_id}/approvals/{approval_id}/deny`
  - `POST /api/v1/runs/{run_id}/resume-approved`
  - `POST /api/v1/scans/web`
  - `GET /api/v1/jobs/{job_id}`
  - `POST /api/v1/jobs/{job_id}/cancel`
- Async job MVP:
  - In-memory daemon job manager.
  - Default `max_concurrent_jobs=1`.
  - Second concurrent running job returns `409 conflict`; no queue in v0.1.2.
  - Scan API defaults to `profile=safe` and `no_external_tools=true`.
  - Missing `target` returns `bad_request`; missing `scope` returns `scope_required`.
  - Cancel is supported for daemon-launched running jobs in the current daemon process.
- API documentation:
  - v0.1.2 API contract: `docs/api/v0.1.2-api-contract.md`
  - v0.1.2 daemon smoke test: `docs/CyberAgent-v0.1.2-Daemon-Smoke-Test.md`

## Runtime API Compatibility Notice

- `runtime.Engine.RunLLMTurn` / `runtime.LLMTurnRunner` are **Deprecated** external engine-seam compatibility APIs. New bounded agent-loop callers should migrate to `runtime.Engine.RunAgentLoop`.
- `runtime.Engine.ExecuteTurn` / `runtime.TurnExecutor` are **Deprecated** external engine-seam compatibility APIs. Agent-loop-shaped callers should migrate to `runtime.Engine.RunAgentLoop`; single planner action execution should migrate to `runtime.Engine.ExecuteAgentLoopAction`.
- Migration window: `current_release_gate`.
- Default compatibility attachment policy: `AttachLLMTurnRunner` and `AttachTurnExecutor` remain default-attached through `agentManager.AttachEngine` and are `retained_until_release_gate`.
- Opt-in flag policy: no new opt-in compatibility flag is introduced in this release note; moving these compatibility attachments behind an opt-in switch is deferred until after the `current_release_gate` docs/API migration notice is complete.

## Security Boundaries

- All `/api/v1/*` endpoints require Bearer token auth, including `healthz`.
- Daemon defaults to local loopback; public daemon mode is not provided.
- Active scans still require explicit scope.
- Safe scan API does not enable external tools by default.
- `nuclei-safe` remains optional and disabled by default.
- `ffuf-low-rate` remains explicit opt-in and approval-gated.
- Run/report/artifact/event APIs resolve paths under the configured runs directory.
- Authorization token values are not written to daemon logs by default.

## Known Limitations

- Job manager state is in-memory; daemon restart loses daemon job status, but run workspaces remain on disk.
- v0.1.2 does not implement a queued job model.
- Cancel only guarantees cancellation for daemon-launched running jobs in the current daemon process.
- `resume-approved` remains synchronous in this release.
- Desktop/Wails, Web multi-user platform, Remote Runner, SSE streaming, and long-term memory remain deferred.
- No tag, push, or GitHub Release is included in this local RC step; remote release requires explicit authorization.

## Upgrade Notes

- Existing CLI/TUI flows remain available.
- Existing v0.1.0/v0.1.1 run directories remain readable through CLI and daemon read APIs.
- Future Desktop/Web work should build on the local daemon API rather than duplicating Core runtime logic.
