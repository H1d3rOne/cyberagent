# CyberAgent v0.1.1

## Highlights

- Stabilization release for the CLI/TUI-first authorized Web/API security analysis MVP.
- Human-in-the-loop approval flow for medium-risk optional steps, including `ffuf-low-rate` resume support.
- Stronger plugin execution boundaries, reproducibility snapshots, artifact indexing, and report/debug UX.

## Features

- CI / release hygiene:
  - GitHub Actions for `gofmt`, `go test`, `go vet`, build, and GoReleaser config check.
  - Reusable release checklist and v0.1.1 smoke test documentation.
- HITL approval MVP:
  - Persisted approval requests for `requires_approval` steps.
  - CLI commands: `approvals list`, `approvals approve`, `approvals deny`.
  - `replay --resume-approved` can resume approved `ffuf-low-rate` steps.
  - Approval actions are recorded in `events.jsonl`, `commands.log`, and bbolt state.
- Plugin hardening:
  - Timeout and stdout/stderr output limits for plugin execution.
  - Output validation before final success recording.
  - Failure taxonomy: `dependency_missing`, `timeout`, `output_limit`, `invalid_output`, `policy_skipped`, `execution_failed`.
  - Bad plugin output no longer breaks an entire safe scan.
- Run reproducibility:
  - `metadata.json` records binary version/commit/date, module, runtime, and command args.
  - `effective_config.json` records the final target/scope/profile/out/plugins/flags.
  - `plugins.snapshot.json` records discovered/enabled/disabled plugin state for the run.
  - `artifacts/index.json` includes artifact `sha256`, `size_bytes`, `mime_type`, and `created_at`.
- CLI / TUI / report UX:
  - `plugins doctor --json` machine-readable output.
  - `report <run-dir> --format md|json`.
  - TUI `Approvals` read-only tab.
  - `scan web` / `replay` skipped-step summary with next actions.
  - `report.md` Plugin Execution Notes and `report.json.plugin_failures` for unresolved plugin skipped/failed states.

## Security Boundaries

- Active scans still require explicit `--scope`.
- Optional external tools remain disabled by default.
- `nuclei-safe` and `ffuf-low-rate` are not enabled automatically.
- `ffuf-low-rate` requires explicit opt-in, explicit approval, and `replay --resume-approved`.
- Approval does not bypass Scope Guard or expand the authorized scope.
- Tool and plugin execution remains auditable through `commands.log`.

## Known Limitations

- `replay --resume-approved` currently supports only approved `ffuf-low-rate` steps.
- TUI approval display is read-only; approve/deny remains CLI-only.
- Desktop/Wails, Web multi-user platform, Remote Runner, and long-term memory remain deferred.
- LLM paths remain optional/experimental and are not required by the Core runtime.

## Upgrade Notes

- Existing v0.1.0 run directories remain readable.
- New v0.1.1 runs include additional reproducibility files and artifact metadata.
- Reports now include `plugin_failures` only for currently unresolved plugin skipped/failed states; resolved plugin steps are omitted after successful resume.
